5. Wave summaries

Wave A — go-live host (must) · 10 days · 62 hours

Buy a cheap Linux GPU VM (Vast.ai first, then RunPod if GPUs are scarce). Download RavenX from Hugging Face. Build llama.cpp and serve it on 127.0.0.1:8080. Clone backend, pip install, set LLAMA_BASE_URL and DATABASE_URL. Install Nuclei, Trivy, Prowler, Checkov, Grype. Run one live scan and one chat. Plus GPU rent (~USD 200–500/month if left on).

Wave B — data that survives restart (must) · 17 days · 96 hours

Switch SQLite to PostgreSQL (compose file already in backend/docker-compose.yml). Add migrations. Confirm tenant_id isolation on findings/assets/trust/risk. Replace in-memory MemoryService with Postgres chat history. Run end-to-end API tests through the whole pipeline.

Wave C — product (should, after host is up) · 18 days · 106 hours

Auto-run Simulation and submit Approval after a plan. Add login or API keys before the VM is public. Point the React screens at real findings/assets/chat. Make live scans async so Nuclei does not block HTTP.

Wave D — later (do not start before A+B) · 38 days · 226 hours

Live KEV/NVD threat feeds, OPA, OpenAI/Anthropic fallback, RAG over findings, real patch/SSH execution (today it only records success), extra scanners (Gitleaks, ZAP, OSV), MCP tools, HTTPS and logging.
